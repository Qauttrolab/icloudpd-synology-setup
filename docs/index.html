1 Übersicht & Architektur

icloudpd lädt Fotos und Videos aus iCloud automatisch auf die Synology NAS herunter. Jeder iCloud Account bekommt einen eigenen Docker Container und einen eigenen Zielordner.

#ContainerFunktionZielordner
1icloudpd-account1Download Account 1/volume2/Backups/icloud/account1/
2icloudpd-account2Download Account 2/volume2/Backups/icloud/account2/
…icloudpd-accountNDownload Account N/volume2/Backups/icloud/accountN/

One-Way Sync: icloudpd lädt nur herunter — Löschen auf der NAS hat keinen Einfluss auf iCloud.

restart: "no" — icloudpd ist ein einmaliger Sync-Job, kein Dauerdienst. Container starten und stoppen automatisch nach dem Download.

2 Voraussetzungen

  • Synology NAS mit DSM 7.3+
  • Container Manager installiert (Paket-Zentrum)
  • SSH-Zugang aktiviert (Systemsteuerung → Terminal & SNMP)
  • Pro iCloud Account ein App-spezifisches Passwort

App-spezifisches Passwort erstellen

Das normale Apple ID Passwort funktioniert nicht. Für jeden Account ein app-spezifisches Passwort erstellen:

1

Browser öffnen → appleid.apple.com → Mit Apple ID anmelden

2

Anmelden & Sicherheit → App-spezifische Passwörter → +

3

Name eingeben: icloudpd → Passwort notieren (Format: xxxx-xxxx-xxxx-xxxx)

4

Diesen Schritt für jeden Account wiederholen

4 ENV Dateien erstellen

4.1 Account-spezifische .env

Pro Account eine eigene .env Datei anlegen:

1

File Station → /volume1/docker/icloudpd/accounts/account1/

2

Neue Textdatei erstellen, Name: .env

3

Inhalt einfügen:

ICLOUD_USER=appleID@example.com
ICLOUD_PASS=xxxx-xxxx-xxxx-xxxx

Berechtigungen: In der File Station → Rechtsklick auf .env → Eigenschaften → Berechtigung → Nur Eigentümer darf lesen/schreiben setzen.

nano /volume1/docker/icloudpd/accounts/account1/.env

Inhalt eintragen, speichern mit Ctrl+O → Enter → Ctrl+X

ICLOUD_USER=appleID@example.com
ICLOUD_PASS=xxxx-xxxx-xxxx-xxxx

Berechtigungen setzen ⚠️ chmod erforderlich

chmod 600 /volume1/docker/icloudpd/accounts/account1/.env

Prüfen:

ls -la /volume1/docker/icloudpd/accounts/account1/.env
# Ergebnis: -rw------- (nur Eigentümer darf lesen)

4.2 Root .env für Docker Compose

Neue Textdatei erstellen, Name: .env

3

Inhalt einfügen — pro Account zwei Zeilen:

ICLOUD_USER_ACCOUNT1=appleID@example.com
ICLOUD_PASS_ACCOUNT1=xxxx-xxxx-xxxx-xxxx

# Account 2 — auskommentiert bis eingerichtet
# ICLOUD_USER_ACCOUNT2=appleID2@example.com
# ICLOUD_PASS_ACCOUNT2=xxxx-xxxx-xxxx-xxxx
nano /volume1/docker/icloudpd/.env
# Account 1 — aktiv
ICLOUD_USER_ACCOUNT1=appleID@example.com
ICLOUD_PASS_ACCOUNT1=xxxx-xxxx-xxxx-xxxx

# Account 2 — auskommentiert bis eingerichtet
# ICLOUD_USER_ACCOUNT2=appleID2@example.com
# ICLOUD_PASS_ACCOUNT2=xxxx-xxxx-xxxx-xxxx

Berechtigungen setzen ⚠️ chmod erforderlich

chmod 600 /volume1/docker/icloudpd/.env

Alle .env auf einmal absichern:

find /volume1/docker/icloudpd/accounts -name ".env" -exec chmod 600 {} \;

5 compose.yaml einrichten

Die compose.yaml liegt in /volume1/docker/icloudpd/. Jeder Account ist ein eigener Service — nicht eingerichtete Accounts werden auskommentiert.

1

Container Manager → Projekte → Erstellen

2

Name: icloudpd | Pfad: /volume1/docker/icloudpd

3

compose.yaml Inhalt einfügen (aus config/compose.yaml in diesem Repo)

4

Speichern — Container werden erstellt aber nicht automatisch gestartet (restart: "no")

Wichtig: Die .env Datei muss bereits in /volume1/docker/icloudpd/ liegen bevor das Projekt erstellt wird.

compose.yaml aus dem Repo kopieren oder manuell erstellen:

nano /volume1/docker/icloudpd/compose.yaml

Danach Container erstellen:

cd /volume1/docker/icloudpd
sudo docker-compose -f compose.yaml up -d icloudpd-account1

Prüfen ob Container erstellt wurde:

sudo docker ps -a | grep icloudpd

compose.yaml Inhalt

services:

  # Account 1 — aktiv
  icloudpd-account1:
    image: icloudpd/icloudpd:latest
    container_name: icloudpd-account1
    restart: "no"
    volumes:
      - ./accounts/account1/cookies:/config
      - /volume2/Backups/icloud/account1:/data
    environment:
      - TZ=Europe/Berlin
    command:
      - icloudpd
      - --username
      - ${ICLOUD_USER_ACCOUNT1}
      - --password
      - ${ICLOUD_PASS_ACCOUNT1}
      - --directory
      - /data
      - --cookie-directory
      - /config
      - --folder-structure
      - "{:%Y/%m}"
      - --auto-delete
      - --log-level
      - info

  # Account 2 — auskommentiert bis eingerichtet
  # icloudpd-account2:
  #   image: icloudpd/icloudpd:latest
  #   container_name: icloudpd-account2
  #   restart: "no"
  #   volumes:
  #     - ./accounts/account2/cookies:/config
  #     - /volume2/Backups/icloud/account2:/data
  #   environment:
  #     - TZ=Europe/Berlin
  #   command:
  #     - icloudpd
  #     - --username
  #     - ${ICLOUD_USER_ACCOUNT2}
  #     - --password
  #     - ${ICLOUD_PASS_ACCOUNT2}
  #     - --directory
  #     - /data
  #     - --cookie-directory
  #     - /config
  #     - --folder-structure
  #     - "{:%Y/%m}"
  #     - --auto-delete
  #     - --log-level
  #     - info

--auto-delete: Löscht Dateien auf der NAS wenn sie in iCloud gelöscht wurden. Weglassen für echtes Backup-Verhalten.

6 2FA Authentifizierung

Die Authentifizierung muss einmalig pro Account interaktiv durchgeführt werden. Das Gerät des jeweiligen Accountinhabers muss dabei erreichbar sein.

Nur per SSH möglich — dieser Schritt erfordert ein interaktives Terminal. Im DSM GUI nicht durchführbar.

6.1 Einzelnen Account authentifizieren

sudo docker run -it --rm \
  -v /volume1/docker/icloudpd/accounts/account1/cookies:/config \
  icloudpd/icloudpd:latest \
  icloudpd \
  --username appleID@example.com \
  --password xxxx-xxxx-xxxx-xxxx \
  --auth-only \
  --cookie-directory /config

Ablauf:

  1. Befehl ausführen — Apple schickt Benachrichtigung ans Gerät
  2. Auf dem Gerät "Erlauben" tippen
  3. 6-stelligen Code im Terminal eingeben → Enter
  4. Authentication completed successfully erscheint

Cookie-Berechtigungen prüfen:

ls -la /volume1/docker/icloudpd/accounts/account1/cookies/

6.2 Alle Accounts auf einmal (auth-all.sh)

Script ausführbar machen ⚠️ chmod erforderlich

chmod +x /volume1/docker/icloudpd/auth-all.sh

Starten — alle Geräte bereithalten:

bash /volume1/docker/icloudpd/auth-all.sh

Cookie-Laufzeit: ~2 Monate. Bei Ablauf erscheint Authentication required im Log — dann Auth für den betroffenen Account wiederholen.

7 run-all.sh einrichten

Das Skript startet alle Accounts nacheinander und wartet bis jeder seinen Download abgeschlossen hat.

7.1 Skript ablegen und ausführbar machen

1

File Station → run-all.sh aus dem Repo nach /volume1/docker/icloudpd/ kopieren

2

Datei bearbeiten — in der ACCOUNTS Liste die aktiven Accounts eintragen

Wichtig: chmod muss per SSH gesetzt werden — die GUI kann Ausführungsrechte nicht setzen.

Ausführungsrecht setzen ⚠️ chmod erforderlich

chmod +x /volume1/docker/icloudpd/run-all.sh

Ebenfalls für auth-all.sh und docker-shutdown.sh:

chmod +x /volume1/docker/icloudpd/auth-all.sh
chmod +x /volume1/docker/scripts/docker-shutdown.sh

Prüfen ob korrekt gesetzt:

ls -la /volume1/docker/icloudpd/*.sh
# Ergebnis: -rwxr-xr-x (x = ausführbar)

Manuell starten (zum Testen):

bash /volume1/docker/icloudpd/run-all.sh

7.2 Accounts in run-all.sh eintragen

1

File Station → /volume1/docker/icloudpd/run-all.sh → Rechtsklick → Bearbeiten

2

ACCOUNTS Liste anpassen — aktive Accounts eintragen, Rest auskommentieren

ACCOUNTS=(
  "account1"
  "account2"
  # "account3"   # noch nicht eingerichtet
)
nano /volume1/docker/icloudpd/run-all.sh

ACCOUNTS Liste anpassen:

ACCOUNTS=(
  "account1"
  "account2"
  # "account3"   # noch nicht eingerichtet
)

8 DSM Aufgabenplaner einrichten

8.1 Täglicher Sync

1

Systemsteuerung → Aufgabenplaner → Erstellen → Geplanter Task → Benutzerdefiniertes Skript

2

Name: icloudpd Sync | Benutzer: root

3

Zeitplan: Täglich, gewünschte Uhrzeit (z.B. 07:00)

4

Skript:

/bin/bash /volume1/docker/icloudpd/run-all.sh >> /volume1/docker/icloudpd/logs/sync.log 2>&1

Voraussetzung: run-all.sh muss ausführbar sein (chmod +x per SSH, siehe Schritt 7).

8.2 Sauberer Docker Shutdown vor NAS-Abschaltung

1

Aufgabenplaner → Erstellen → Benutzerdefiniertes Skript

2

Name: Docker Shutdown | Benutzer: root | Zeit: 22:55 (5 Min vor Abschaltung)

3

Skript:

/bin/bash /volume1/docker/scripts/docker-shutdown.sh

Script-Ordner anlegen und chmod setzen ⚠️ chmod erforderlich

mkdir -p /volume1/docker/scripts
chmod +x /volume1/docker/scripts/docker-shutdown.sh

Manuell testen:

bash /volume1/docker/scripts/docker-shutdown.sh

11 Hinweise & Besonderheiten

ThemaInfo
ErstdownloadKann Stunden bis Tage dauern — Apple drosselt den Download serverseitig
Abgebrochener SyncKein Problem — beim nächsten Start wird genau da weitergemacht. Keine Duplikate.
Live PhotosWerden als zwei Dateien gespeichert: .HEIC + _HEVC.MOV
GPS & EXIFBleiben vollständig erhalten
--auto-deleteIn iCloud gelöschte Dateien werden auch auf der NAS gelöscht. Weglassen für echtes Backup.
NAS löschenHat keinen Einfluss auf iCloud — icloudpd ist One-Way
Cookie-Ablauf~2 Monate. Bei Authentication required im Log → Auth erneut durchführen
chmod 600.env Dateien schützen — nur root darf lesen. Immer nach dem Erstellen setzen.
chmod +xShell-Skripte müssen ausführbar sein. Einmalig per SSH setzen.
