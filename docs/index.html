1 Übersicht & Architektur

icloudpd lädt Fotos und Videos aus iCloud automatisch auf die Synology NAS herunter. Jeder iCloud Account bekommt einen eigenen Docker Container und einen eigenen Zielordner.

#ContainerFunktionZielordner
1icloudpd-account1Download Account 1/volume2/Backups/icloud/account1/
2icloudpd-account2Download Account 2/volume2/Backups/icloud/account2/
…icloudpd-accountNDownload Account N/volume2/Backups/icloud/accountN/

One-Way Sync: icloudpd lädt nur herunter — Löschen auf der NAS hat keinen Einfluss auf iCloud.

restart: "no" — icloudpd ist ein einmaliger Sync-Job, kein Dauerdienst. Container starten und stoppen automatisch.

2 Voraussetzungen

  • Synology NAS mit DSM 7.3+
  • Container Manager installiert (Paket-Zentrum)
  • SSH-Zugang aktiviert (Systemsteuerung → Terminal & SNMP)
  • Pro iCloud Account ein App-spezifisches Passwort

App-spezifisches Passwort erstellen

Das normale Apple ID Passwort funktioniert nicht. Für jeden Account ein app-spezifisches Passwort erstellen:

1

Browser öffnen → appleid.apple.com → Mit Apple ID anmelden

2

Anmelden & Sicherheit → App-spezifische Passwörter → +

3

Name eingeben: icloudpd → Passwort notieren (Format: xxxx-xxxx-xxxx-xxxx)

4

Diesen Schritt für jeden Account wiederholen

3 Ordnerstruktur anlegen

Configs und Cookies auf volume1 (SSD), Foto/Video-Daten auf volume2 (HDD).

3.1 Config-Ordner (volume1 / SSD)

Pro Account einen Ordner anlegen — Namen entsprechend anpassen:

mkdir -p /volume1/docker/icloudpd/accounts/account1/cookies
mkdir -p /volume1/docker/icloudpd/accounts/account2/cookies
mkdir -p /volume1/docker/icloudpd/logs

3.2 Backup-Ordner (volume2 / HDD)

mkdir -p /volume2/Backups/icloud/account1
mkdir -p /volume2/Backups/icloud/account2

3.3 Ergebnis

/volume1/docker/icloudpd/          ← Configs, Skripte, Cookies (SSD)
├── accounts/
│   ├── account1/
│   │   ├── .env                   ← Zugangsdaten (chmod 600!)
│   │   └── cookies/               ← Session-Token (automatisch befüllt)
│   └── account2/
│       ├── .env
│       └── cookies/
├── logs/                          ← Sync-Logs
├── compose.yaml                   ← Container-Definitionen
├── .env                           ← Zugangsdaten für Docker Compose
├── run-all.sh                     ← Täglicher Sync
└── auth-all.sh                    ← Einmalige 2FA-Authentifizierung

/volume2/Backups/icloud/           ← Fotos & Videos (HDD)
├── account1/
│   └── 2024/
│       ├── 01/
│       └── 02/
└── account2/

4 ENV Dateien erstellen

4.1 Account-spezifische .env

Pro Account eine eigene .env Datei — nur dieser Account kann die Zugangsdaten lesen.

# /volume1/docker/icloudpd/accounts/account1/.env
[email protected]
ICLOUD_PASS=xxxx-xxxx-xxxx-xxxx

4.2 Root .env für Docker Compose

Diese Datei liegt direkt in /volume1/docker/icloudpd/ und wird von Docker Compose automatisch eingelesen.

# /volume1/docker/icloudpd/.env

# Account 1
[email protected]
ICLOUD_PASS_ACCOUNT1=xxxx-xxxx-xxxx-xxxx

# Account 2
[email protected]
ICLOUD_PASS_ACCOUNT2=xxxx-xxxx-xxxx-xxxx

# Weitere Accounts auskommentiert bis eingerichtet:
# [email protected]
# ICLOUD_PASS_ACCOUNT3=xxxx-xxxx-xxxx-xxxx

4.3 Dateien absichern

chmod 600 /volume1/docker/icloudpd/.env
chmod 600 /volume1/docker/icloudpd/accounts/account1/.env
chmod 600 /volume1/docker/icloudpd/accounts/account2/.env

Sicherheit: Die .env Dateien enthalten Zugangsdaten. chmod 600 stellt sicher dass nur root sie lesen kann.

5 compose.yaml einrichten

Jeder Account ist ein eigener Service. Nicht eingerichtete Accounts werden auskommentiert.

# /volume1/docker/icloudpd/compose.yaml

services:

  # ---------------------------------------------------------------------------
  # ACCOUNT 1 — aktiv
  # ---------------------------------------------------------------------------
  icloudpd-account1:
    image: icloudpd/icloudpd:latest
    container_name: icloudpd-account1
    restart: "no"          # Einmaliger Job — nicht dauerhaft laufen lassen
    volumes:
      - ./accounts/account1/cookies:/config    # Session-Cookie
      - /volume2/Backups/icloud/account1:/data # Zielordner Fotos/Videos
    environment:
      - TZ=Europe/Berlin
    command:
      - icloudpd
      - --username
      - ${ICLOUD_USER_ACCOUNT1}
      - --password
      - ${ICLOUD_PASS_ACCOUNT1}
      - --directory
      - /data
      - --cookie-directory
      - /config
      - --folder-structure
      - "{:%Y/%m}"          # Ordnerstruktur: /data/2024/03/foto.jpg
      - --auto-delete       # Entfernen wenn in iCloud gelöscht — weglassen für echtes Backup
      - --log-level
      - info

  # ---------------------------------------------------------------------------
  # ACCOUNT 2 — auskommentiert bis eingerichtet
  # ---------------------------------------------------------------------------
  # icloudpd-account2:
  #   image: icloudpd/icloudpd:latest
  #   container_name: icloudpd-account2
  #   restart: "no"
  #   volumes:
  #     - ./accounts/account2/cookies:/config
  #     - /volume2/Backups/icloud/account2:/data
  #   environment:
  #     - TZ=Europe/Berlin
  #   command:
  #     - icloudpd
  #     - --username
  #     - ${ICLOUD_USER_ACCOUNT2}
  #     - --password
  #     - ${ICLOUD_PASS_ACCOUNT2}
  #     - --directory
  #     - /data
  #     - --cookie-directory
  #     - /config
  #     - --folder-structure
  #     - "{:%Y/%m}"
  #     - --auto-delete
  #     - --log-level
  #     - info

Container erstellen

cd /volume1/docker/icloudpd
sudo docker-compose -f compose.yaml up -d icloudpd-account1

Wichtig: Container müssen einmalig via docker-compose up erstellt werden bevor run-all.sh sie mit docker start starten kann.

6 2FA Authentifizierung

Die Authentifizierung muss einmalig pro Account interaktiv durchgeführt werden. Das Gerät des jeweiligen Accountinhabers muss dabei erreichbar sein (iPhone, iPad oder Mac).

Interaktiv: Dieser Befehl muss im SSH-Terminal ausgeführt werden — nicht im Hintergrund. Apple schickt einen 6-stelligen Code ans Gerät.

6.1 Auth für einzelnen Account

sudo docker run -it --rm \
  -v /volume1/docker/icloudpd/accounts/account1/cookies:/config \
  icloudpd/icloudpd:latest \
  icloudpd \
  --username [email protected] \
  --password xxxx-xxxx-xxxx-xxxx \
  --auth-only \
  --cookie-directory /config

6.2 Ablauf

  1. Befehl ausführen — Apple schickt Benachrichtigung ans Gerät
  2. Auf dem Gerät "Erlauben" tippen
  3. 6-stelligen Code im Terminal eingeben → Enter
  4. Authentication completed successfully erscheint
  5. Cookie wird in accounts/account1/cookies/ gespeichert

Cookie-Laufzeit: ~2 Monate. Bei Ablauf erscheint Authentication required im Log — dann Auth für den betroffenen Account wiederholen.

6.3 auth-all.sh — Auth für alle Accounts

Für den Erstaufbau mit mehreren Accounts empfiehlt sich das auth-all.sh Skript — es führt die Auth für jeden Account nacheinander durch und wartet auf Bestätigung.

bash /volume1/docker/icloudpd/auth-all.sh

7 run-all.sh — Automatisierter Sync

Das Skript startet alle Accounts nacheinander. Es wartet bis jeder Container seinen Download abgeschlossen hat bevor der nächste startet.

#!/bin/bash
# =============================================================================
# run-all.sh — Täglicher iCloud Sync für alle Accounts
# Ablage: /volume1/docker/icloudpd/run-all.sh
#
# NEUEN ACCOUNT HINZUFÜGEN:
#   1. Account in compose.yaml einkommentieren
#   2. sudo docker-compose -f compose.yaml up -d icloudpd-NAME
#   3. Account hier in ACCOUNTS Liste eintragen
# =============================================================================

LOG_DIR="/volume1/docker/icloudpd/logs"
DELAY=0  # Sekunden Pause zwischen Accounts (0 = sofort nach Abschluss)

mkdir -p "$LOG_DIR"

echo "============================================="
echo " icloudpd Sync: $(date '+%Y-%m-%d %H:%M:%S')"
echo "============================================="

# Aktive Accounts — auskommentieren = wird nicht gesynct
ACCOUNTS=(
  "account1"
  "account2"
  # "account3"   # noch nicht eingerichtet
  # "account4"   # fertig, kein weiterer Sync nötig
)

TOTAL=${#ACCOUNTS[@]}
COUNT=0

for account in "${ACCOUNTS[@]}"; do
  COUNT=$((COUNT + 1))
  echo ""
  echo "--- Account: $account ($COUNT/$TOTAL) | $(date '+%H:%M:%S') ---"

  if ! docker inspect "icloudpd-$account" > /dev/null 2>&1; then
    echo "WARNUNG: Container icloudpd-$account existiert nicht"
    echo "         → docker-compose up -d icloudpd-$account ausführen"
    continue
  fi

  docker start "icloudpd-$account"
  docker wait "icloudpd-$account"

  echo "✓ $account fertig: $(date '+%H:%M:%S')"
  sleep $DELAY
done

echo ""
echo "============================================="
echo " Alle Accounts fertig: $(date '+%Y-%m-%d %H:%M:%S')"
echo "============================================="

Skript ausführbar machen

chmod +x /volume1/docker/icloudpd/run-all.sh

docker wait: Das Skript wartet bis jeder Container seinen Job abgeschlossen hat. Wird der Sync durch den Shutdown-Task unterbrochen, macht icloudpd beim nächsten Start genau da weiter wo er aufgehört hat.

8 DSM Aufgabenplaner einrichten

8.1 Täglicher Sync

1

Systemsteuerung → Aufgabenplaner → Erstellen → Geplanter Task → Benutzerdefiniertes Skript

2

Name: icloudpd Sync | Benutzer: root

3

Zeitplan: Täglich, gewünschte Uhrzeit (z.B. 07:00)

4

Skript:

/bin/bash /volume1/docker/icloudpd/run-all.sh >> /volume1/docker/icloudpd/logs/sync.log 2>&1

8.2 Sauberer Shutdown vor NAS-Abschaltung

Wenn die Synology täglich abgeschaltet wird, empfiehlt sich ein Shutdown-Task der alle Container sauber beendet — besonders wichtig für Datenbank-Container wie Paperless oder Immich.

1

Aufgabenplaner → Erstellen → Benutzerdefiniertes Skript

2

Name: Docker Shutdown | Benutzer: root | Zeit: 22:55

3

Skript:

/bin/bash /volume1/docker/scripts/docker-shutdown.sh

9 Neuen Account hinzufügen

  1. App-spezifisches Passwort erstellen → appleid.apple.com
  2. Ordner anlegen: 
    mkdir -p /volume1/docker/icloudpd/accounts/neuername/cookies
mkdir -p /volume2/Backups/icloud/neuername
  3. Account .env befüllen: 
    [email protected]
ICLOUD_PASS=xxxx-xxxx-xxxx-xxxx
  4. Root .env um neue Variablen ergänzen
  5. Service-Block in compose.yaml einkommentieren
  6. Container erstellen: 
    cd /volume1/docker/icloudpd && sudo docker-compose -f compose.yaml up -d icloudpd-neuername
  7. 2FA Auth durchführen (Schritt 6)
  8. Account in run-all.sh ACCOUNTS Liste eintragen

Account deaktivieren (kein weiterer Sync)

  1. In run-all.sh den Account in der ACCOUNTS Liste auskommentieren
  2. In compose.yaml den Service-Block auskommentieren

Daten bleiben erhalten — deaktivierte Accounts werden einfach nicht mehr gesynct. Fotos und Videos auf der NAS bleiben unberührt.

11 Hinweise & Besonderheiten

ThemaInfo
ErstdownloadKann je nach Mediatheksgröße Stunden bis Tage dauern — Apple drosselt den Download serverseitig
Abgebrochener SyncKein Problem — beim nächsten Start wird genau da weitergemacht. Keine Duplikate
Live PhotosWerden als zwei Dateien gespeichert: .HEIC + _HEVC.MOV
GPS & EXIFBleiben vollständig erhalten — Immich und andere Apps können die Daten direkt nutzen
--auto-deleteMit diesem Flag: Dateien die in iCloud gelöscht wurden, werden auch auf der NAS gelöscht. Weglassen für echtes Backup-Verhalten
NAS löschenHat keinen Einfluss auf iCloud — icloudpd ist One-Way
Cookie-Ablauf~2 Monate. Bei Authentication required im Log → Auth erneut durchführen
Mehrere AccountsApple sieht alle Requests von derselben IP — bisher kein Throttling bekannt bei normalem Betrieb
